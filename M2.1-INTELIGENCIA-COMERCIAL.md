# M2.1 — Inteligência comercial / métricas reais

## Escopo

A M2.1 transforma somente os eventos reais do M1 no dataset `pnm_commercial_m1` em consultas comerciais reproduzíveis e auditáveis. Não cria dashboard, banco paralelo, novos eventos, novas lojas ou infraestrutura de produção.

`affiliate_click` continua significando saída do Preço na Mira para a loja. Não confirma compra, venda ou comissão.

## Schema M1 confirmado

O Worker grava um único índice e arrays ordenados no Workers Analytics Engine:

| Campo Analytics Engine | Semântica M1 |
| --- | --- |
| `timestamp` | timestamp automático do Analytics Engine |
| `index1` | evento: `page_view` ou `affiliate_click` |
| `blob1` | versão do schema: `m1-v1` |
| `blob2` | evento redundante para auditoria |
| `blob3` | página/origem |
| `blob4` | `page_type` |
| `blob5` | `product_id` |
| `blob6` | `store` |
| `blob7` | `placement` |
| `blob8` | `utm_source` |
| `blob9` | `utm_medium` |
| `blob10` | `utm_campaign` |
| `blob11` | `referrer_host` |
| `blob12` | host que recebeu o evento |
| `double1` | peso escrito pelo M1 (`1`) |
| `_sample_interval` | peso de amostragem fornecido pelo Analytics Engine |

O Worker atual aceita somente `page_view` e `affiliate_click`. O binding continua sendo `PNM_ANALYTICS` e aponta para `pnm_commercial_m1`.

### Placement M1

`card`, `primary`, `sidebar`, `sticky`, `related`, `search_result`, `saved`, `cart`, `comparison`, `project`, `studio`, `small_spaces`, `obra_base`, `dewalt_pending`.

A fila DeWalt ainda não normalizada pode usar `product_id=unknown` com `placement=dewalt_pending`; isso é esperado e não deve ser tratado automaticamente como erro.

## Consultas disponíveis

O catálogo está em `scripts/m2-1-analytics-lib.mjs` e é executado por `scripts/m2-1-analytics.mjs`.

### Métricas

- `total_page_views` — total de `page_view` válidos.
- `total_affiliate_clicks` — total de `affiliate_click` válidos.
- `affiliate_clicks_by_product` — cliques por produto.
- `affiliate_clicks_by_page` — cliques por página/origem.
- `affiliate_clicks_by_placement` — cliques por placement.
- `affiliate_clicks_by_store` — cliques por loja.
- `top_products` — 25 produtos mais clicados.
- `top_commercial_pages` — 25 páginas com mais cliques comerciais.
- `events_by_hour` — distribuição temporal horária em UTC.
- `affiliate_click_rate_by_page` — taxa de clique afiliado por página, calculada somente entre `affiliate_click` e `page_view` da mesma dimensão `page`.

As contagens usam `_sample_interval` para continuar corretas caso o Analytics Engine aplique amostragem.

### Taxa de clique afiliado

A M2.1 não usa a expressão “taxa de conversão”. Não há confirmação de venda do Mercado Livre.

`affiliate_click_rate_by_page` é uma razão de eventos:

`affiliate_clicks da página / page_views da mesma página × 100`

Ela pode ultrapassar 100% porque uma visualização pode gerar mais de um clique e o M1 não possui identificador persistente de usuário/sessão para deduplicação comercial. Portanto ela deve ser lida como intensidade de clique de saída, não como pessoas únicas e nunca como vendas.

## Qualidade dos dados

- `unknown_event_types` — detecta tipos desconhecidos ou divergência entre `index1` e `blob2`.
- `missing_affiliate_click_fields` — detecta ausência de `product_id`, `store`, `page` ou `placement`.
- `unexpected_affiliate_values` — detecta loja diferente de `mercado_livre`, placement fora do vocabulário M1 ou host inesperado.
- `schema_incompatibilities` — detecta versão/layout incompatível, peso diferente de 1 e campos incompatíveis com o tipo do evento.
- `possible_technical_duplicates` — heurística para linhas idênticas no mesmo timestamp.

A verificação de duplicação é propositalmente conservadora: sem `event_id` ou `session_id`, linhas iguais no mesmo timestamp podem representar ações legítimas. A consulta somente sinaliza candidatos e nunca apaga ou corrige dados.

## Execução

Listar consultas:

```bash
npm run analytics:m2-1 -- list
npm run analytics:m2-1 -- list metrics
npm run analytics:m2-1 -- list quality
```

Exibir o SQL sem executar:

```bash
npm run analytics:m2-1 -- sql top_products
```

Para consultar dados reais, crie um token Cloudflare com permissão mínima `Account Analytics Read` e forneça as credenciais somente por variáveis de ambiente:

```bash
PNM_CF_ACCOUNT_ID=<account_id> \
PNM_CF_ANALYTICS_TOKEN=<token> \
npm run analytics:m2-1 -- run top_products
```

PowerShell:

```powershell
$env:PNM_CF_ACCOUNT_ID="<account_id>"
$env:PNM_CF_ANALYTICS_TOKEN="<token>"
npm run analytics:m2-1 -- run top_products
Remove-Item Env:\PNM_CF_ANALYTICS_TOKEN
```

Executar um grupo completo:

```bash
npm run analytics:m2-1 -- run-group metrics
npm run analytics:m2-1 -- run-group quality
```

O executor usa `POST https://api.cloudflare.com/client/v4/accounts/{account_id}/analytics_engine/sql`. O token nunca é gravado no repositório, no Worker, no dataset ou na saída normal do script.

## Segurança e preservação

- não versionar `PNM_CF_ACCOUNT_ID` nem `PNM_CF_ANALYTICS_TOKEN`;
- não adicionar segredo ao `wrangler.jsonc` para esta fase;
- não criar endpoint público de leitura do Analytics Engine;
- não alterar `src/worker.mjs`, `scripts/m1-client-fragment.js` ou links afiliados para executar M2.1;
- não adicionar Amazon ou Shopee;
- não alterar ou apagar dados históricos;
- consultas da M2.1 são somente leitura.

## Validação

`npm run test:m2-1` valida o mapeamento do schema, o catálogo mínimo de métricas/qualidade, nomenclatura, ausência de lojas extras e o cliente da SQL API com `fetch` simulado.

`npm run check` executa build, testes M1, testes M2.1, `audit:strict` (incluindo P9) e `wrangler deploy --dry-run`.
